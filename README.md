## ✨ 核心特性

- 🌐 **内置登录窗口自动获取 Cookie (全新 v1.9.0)**：
  - 在配置中心点 **「🌐 打开登录窗口自动获取 Cookie」**，容器内会启动一个**可见的 Chromium**（通过 noVNC 内嵌小窗直接显示在 WebUI 里），你在窗口里正常登录微软账号即可；
  - 登录完成后点 **「✅ 保存并填入 Cookie」**，后端直接把**完整** Cookie 串抓下来 → 校验登录态 → 只有校验通过才写进账号，不再需要按 F12 手工复制；
  - 登录窗口与积分任务**共用浏览器资源锁**，同一时间只跑一个 Chromium；窗口打开期间自动任务让路，关闭后立即释放，不留「窗口关了但浏览器还在跑」的僵尸；
  - 超时保护：默认 30 分钟未保存自动关闭并释放资源（`LOGIN_WINDOW_TIMEOUT_MIN`，设 `0` 可关闭该保护）；
  - 登录态按账号隔离保存在持久化 profile 里（`data/login-profile/`），关掉窗口再打开不需要重新输密码；
  - noVNC 通过现有 `5308` 端口反向代理，静态资源与 WebSocket 升级握手都走与 WebUI 相同的 `server.authPassword`，不会绕过密码；
  - 纯无头环境（`MSR_VISIBLE=0`）下会明确提示改用「手工粘贴完整 Cookie」，不会静默失败。
- 🍪 **Cookie 粘贴容错**：
  - 支持**完整 Cookie 串**、**Cookie-Editor 导出的 JSON**、**Safari / Excel 表格复制**（制表符分隔），以及带 `Cookie:` 前缀、整体带引号的写法，全部自动规整成 `名=值; 名=值`；
  - 缺少 `_U` 时，会从 `SRCHUID` / `_EDGE_S` / `SRCHHPGUSR` 里的 `GUID=` **交叉校验后**自动补齐；多处来源不一致时拒绝猜，提示重新复制（宁可不补，也不注入一个错的 `_U` 把搜索计到别的身份上）；
  - 只贴了**某一个 Cookie 的值**时，明确提示「这只是一个值，需要完整串」，并给出用 `document.cookie` 复制的具体步骤，不再含糊地报一句「Cookie 已过期」；
  - 只贴了单个 `名=值` 而账号里已有完整 Cookie 时按**合并**处理，不会把 `MUID` / `RPSSecAuth` 一起冲掉；
  - 粘贴后即时给出「共 N 项 / 缺什么 / 自动补了什么」的清单。
- 💬 **QQ 机器人推送 (全新 v1.9.0)**：
  - 通知渠道新增**官方 QQ 机器人**（OpenAPI v2），配置 AppID、AppSecret、发送目标（群聊 `group_openid` / 私聊 `user_openid` / 频道 `channel_id`）与对应 OpenID；
  - `POST https://bots.qq.com/app/getAppAccessToken` 换取 `access_token`，按 AppID 缓存到过期前 60 秒，避免频繁取票被平台限频；
  - 发消息走 `POST /v2/groups/{group_openid}/messages`（私聊 `/v2/users/...`、频道 `/v2/channels/...`），`Authorization: QQBot {access_token}`，`msg_type: 0` 纯文本；
  - 不带 `msg_id` 属于**主动消息**，受平台每月主动推送额度限制；额度用尽时平台返回 `err_code`（如 `40034005`），日志里会原样记录，便于区分「没配好」和「额度用完」。
- 🖥️ **Playwright / Chromium 真机拟人引擎 (全新 v1.4.0 重大升级)**：
  - 彻底抛弃纯 HTTP GET 的易风控搜索方式，引入真正的无头浏览器内核；
  - 模拟真实键盘输入事件流 (`keydown`/`keypress`/`keyup`)，带 50~120ms 随机按键延时与自动补全触发；
  - 模拟回车提交与鼠标滚轮向下浏览搜索结果，100% 触发微软官方反欺诈遥测，彻底免疫“搜索暂停 / 15分钟冷却限制”；
  - **用完即焚极速释放**：仅在搜索期间唤醒浏览器，任务结束立即关闭释放，平时常驻内存低至 ~60MB。
- 🕒 **14 个一小时运行档位 (09:00-23:00)**：

### 方法 1：使用 Docker Compose 部署（推荐，群晖/威联通/极空间/VPS）

1. 在服务器或 NAS 上创建一个项目目录，例如 `ms-rewards`：
```bash
mkdir -p ms-rewards && cd ms-rewards
```

2. 在该目录下创建 `docker-compose.yml` 文件：
```yaml
services:
  microsoft-rewards:
    image: wangheqiang/microsoft-rewards-docker:latest
    # 或者使用 GitHub 镜像：
    # image: ghcr.io/wangheqiang530/microsoft-rewards-docker:latest
    # 想在本地从源码构建时，改用下一行（需要本仓库源码）：

    container_name: ms-rewards
    restart: unless-stopped
    ports:
      - "5308:5308"
    environment:
      - TZ=Asia/Shanghai
      - PORT=5308
      # 可见浏览器：供「微软账号登录窗口」通过 noVNC 内嵌小窗使用（0 = 关闭）
      - MSR_VISIBLE=${MSR_VISIBLE:-1}
      - NOVNC_PASSWORD=${NOVNC_PASSWORD:-}
      - NOVNC_PORT=6080
      - VNC_PORT=5900
      # 登录窗口超过该分钟数未保存则自动关闭；设为 0 关闭保护
      - LOGIN_WINDOW_TIMEOUT_MIN=${LOGIN_WINDOW_TIMEOUT_MIN:-30}
    volumes:
      - ./data:/app/data
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
```

3. 启动容器：
```bash
docker compose up -d
```

4. 启动后，打开浏览器访问：`http://<NAS或VPS的IP>:5308`，即可进入现代化控制台！

### 环境变量说明

| 环境变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `TZ` | `Asia/Shanghai` | 容器时区，定时调度与日志时间都按它计算 |
| `PORT` | `5308` | WebUI 端口（容器内），宿主机映射保持一致即可 |
| `MSR_VISIBLE` | `1` | 是否在容器内启动 Xvfb 可见浏览器；`0` 关闭后「登录窗口自动获取 Cookie」不可用，只能手工粘贴完整 Cookie |
| `NOVNC_PASSWORD` | 空 | noVNC 的访问密码；留空时容器内 x11vnc 不设密码，但端口不映射到宿主机，且仍需通过 WebUI 鉴权才能进入 |
| `NOVNC_PORT` / `VNC_PORT` | `6080` / `5900` | 容器内 websockify 与 x11vnc 的端口，无需映射到宿主机 |
| `LOGIN_WINDOW_TIMEOUT_MIN` | `30` | 登录窗口超过该分钟数未保存会自动关闭并释放浏览器资源；`0` 关闭该保护 |
| `CHROMIUM_PATH` | `/usr/bin/chromium` | 浏览器内核路径；想改用容器内的 Edge 时改这里 |
| `MSR_DATA_DIR` | `./data` | 数据目录，本地开发时可用它指到临时目录 |

## 📁 数据持久化与文件说明

容器内 `/app/data` 目录通过 Volume 挂载到宿主机本地的 `./data` 目录，所有关键数据均已完整暴露并持久化存储，无需进入容器内部即可直接在 NAS 文件管理套件或宿主机中查看、修改或迁移备份：

| 文件路径 | 用途说明 |
| :--- | :--- |
| `data/config.json` | **核心配置文件**（包含微软凭据 Cookie/Token、代理配置、任务开关、通知渠道等） |
| `data/app.log` | **持久化运行日志文件**（实时记录后台自动打卡细节、接口请求与排查日志） |
| `data/stats.json` | **任务状态快照**（记录当日积分、任务配额进度与连签天数） |
| `data/history.json` | **历史积分账单数据**（用于前端 7 日 / 30 日历史趋势柱状图明细展示） |
| `data/sessions/` | **每个账号的浏览器会话**（Cookie 与 localStorage，权限 0600，用于跨次复用同一台「浏览器」；不含身份 Cookie `_U`） |
| `data/login-profile/` | **登录窗口的浏览器 profile**（按账号隔离，保存登录态；关掉窗口再打开不需要重新输密码，删除账号时一并清理） |

## 💡 小白 1 分钟配置上手指南

初次打开 Web 控制台时，点击右上角的 **「💡 新手配置向导」**，按以下顺序完成：

### 步骤 1：网络出口与代理
**必须先确认代理，再绑定 Cookie 或 Token。** 凭据测试与换取 Token 会立即发起真实微软会话。

- 如果你的设备在**中国国内家庭宽带 / NAS**：保持默认直连即可。
- 如果你的设备在**境外 VPS**：
  1. 在「网络与代理」中点击 **「＋ 添加代理」**，可保存多套国内节点；
  2. 为每套节点点击 **「测试」**，确认出口 IP、归属地为 **中国大陆 (CN)** 且代理延迟正常；
  3. 在「账号与凭证」中为每个账号选择 **跟随全局 / 直连 / 指定代理**，避免多账号共用同一出口。

### 步骤 2：移动端授权 (OAuth Token)
1. 点击向导中的 **「🔑 打开微软官方登录授权页」**，在弹出的微软官网登录你的账号；
2. 登录同意后，浏览器会跳转至类似 `https://login.live.com/oauth20_desktop.srf?code=M.C508_...` 的地址；
3. 将地址栏中的完整 URL 复制粘贴到输入框中，点击 **「一键换取并保存 Token」**。
> ✨ 提示：系统会自动捕获并持久化保存 Refresh Token，后续系统会**永久自动无感续期**，无需再次操作。

### 步骤 3：网页端 Cookie 配置

网页端 Cookie 有两条获取路径，**推荐第一条**。

#### 路线 A（推荐）：打开登录窗口自动获取
1. 在配置中心（或「新建账号」弹窗、配置向导）点 **「🌐 打开登录窗口自动获取 Cookie」**；
2. WebUI 会弹出内嵌小窗，显示的正是容器里那台 Chromium 的真实画面（noVNC 反向代理，仍然走现有的 `5308` 端口）；
3. 在小窗里像平时一样登录微软账号，登录成功后等页面右上角出现头像 / 积分数字；
4. 点小窗底部 **「✅ 保存并填入 Cookie」**：后端会把浏览器里的**完整** Cookie 抓下来、校验登录态，通过后直接写进账号并关闭窗口；
5. 校验没通过时窗口**不会**关闭，可以继续在窗口里处理（比如再走一次验证），确认登录态后再点保存。

> 需要容器内的可见浏览器（`MSR_VISIBLE=1`，默认开启）。纯无头部署（`MSR_VISIBLE=0`）时点这个按钮会明确提示改用路线 B。

#### 路线 B：手工粘贴完整 Cookie
1. 在电脑浏览器登录 [rewards.bing.com/dashboard](https://rewards.bing.com/dashboard)；
2. 按 `F12` 打开开发者工具，切到 **Console**，执行 `document.cookie`，把输出的**整串**复制出来（形如 `_U=...; MUID=...; RPSSecAuth=...`）；
   - 也可以在【网络 / Network】里抓任意请求的 `Cookie` 请求头，或在【应用程序 / Application → Cookies】中复制；
3. 必须是**完整串**：只填某一个 Cookie 的**值**不生效（系统会直接提示「这只是一个值，需要完整串」，而不是含糊地报「Cookie 已过期」）；
4. **确认包含 `_U=...`**：没有 `_U` 时网页端能登录，但 PC 搜索不会计分（`KievRPSSecAuth` 不能替代 `_U`）。粘贴后如果缺 `_U`，系统会尝试从 `SRCHUID` / `_EDGE_S` / `SRCHHPGUSR` 里的 `GUID=` **交叉校验后**自动补齐，并在界面上说明补了什么、还缺什么；
5. 支持 Cookie-Editor 导出的 JSON、Safari / Excel 表格复制的制表符格式、带 `Cookie:` 前缀的写法，都会被自动规整成 `名=值; 名=值`；
6. 粘贴后点击 **「测试 Cookie 有效性」**，确认显示「Cookie 有效」并能看到「共 N 项」的清单。

配置完成后，点击 **「▶️ 立即执行」**，即可在控制台实时看到打卡日志与积分上涨！

## ⚙️ 进阶配置与高级功能

点击右上角 **「⚙️ 配置中心」** 可进行详细参数微调：

- **任务开关**：可单独开启/关闭签到、新闻阅读、PC 搜索、活动卡片、桌面专属任务；
- **搜索节奏与防风控**：每次搜索的基础间隔（默认 60 秒）与随机浮动（默认 60 秒，只会延后）全局生效，20 次搜索最慢限制在 40 分钟内；**停滞保护**默认「连续 5 次搜索官网进度不涨就主动停手」，可自行调整；支持自定义搜索词源（离线词库或热搜 API）；
- **账号身份与凭据配对**：PC 搜索只依赖网页 Cookie 的 `_U` 身份和官网返回的搜索等级配额；移动端 Token 仅用于签到与阅读。重新导入 Cookie/Token 后会清空旧体检结论，Cookie 的 `_U` 变化时同步清空旧账号进度；Token 与 Cookie 无法确认属于同一账号时，移动端任务会跳过而不是盲目执行；
- **定时巡检调度**：
  - 默认 Cron：`*/25 * * * *`（每 25 分钟后台巡检一次）；
  - 支持自定义，如 `0 8,12,20 * * *`（每天 8 点、12 点、20 点执行）；
- **消息推送**：
  - 支持配置企业微信、钉钉（关键词需带 `#`）、飞书、Bark、PushMe、Telegram 与 **QQ 机器人**，面板提供一键发送测试消息。
  - **QQ 机器人**（官方 OpenAPI v2）需要填 AppID、AppSecret、发送目标与对应 OpenID：群聊填 `group_openid`、私聊填 `user_openid`、频道填 `channel_id`，AppID 与 AppSecret 在 QQ 开放平台的机器人管理页获取。
  - access_token 由程序按 AppID 缓存（到期前 60 秒刷新），不需要手工维护；不带 `msg_id` 的消息属于**主动消息**，受平台每月主动推送额度限制，额度用尽时平台会返回错误码（如 `40034005`），日志里原样记录，便于区分额度问题与配置问题。

## 🧬 浏览器指纹与反风控说明

自动化最容易出问题的地方不是「伪装得不够像」，而是**前后不一致**——同一个请求里几个字段互相打架。
本项目在 v1.6.1 做过一次完整排查，结论如下。

### 指纹的单一来源

所有身份常量集中在 `src/core/fingerprint.js`。UA、客户端提示（`Sec-CH-UA`）、`navigator.platform`
三者由同一份常量派生，不允许各模块自行硬编码——历史上正是因为各处硬编码不同版本，
出现过「UA 说 Edge 131、客户端提示说真实版本、platform 说真实系统」这种三处矛盾。

升级基础镜像后如果 Chromium 主版本变了，启动日志会打印提醒，需要同步更新该文件里的 `CHROME_MAJOR`。

### 两条通道的身份是分开的（这是正确的）

| 通道 | 身份 | 说明 |
| :--- | :--- | :--- |
| Playwright 浏览器 | Windows + Chrome | PC 搜索、打孔卡、单次测搜 |
| 移动端 DAPI | Android + BingSapphire App | App 签到、新闻阅读 |
| 桌面客户端任务 | macOS + MSRewards/Desktop | 桌面专属打孔卡 |

移动端和桌面客户端的请求**不应该**带浏览器头——它们本来就是 App 客户端，带浏览器头反而更可疑。

### 为什么是 Chrome 而不是 Edge

镜像里安装的是 Debian 的 **Chromium**。Edge 与 Chromium 的版本号并不同步
（Debian chromium 已到 150 时，Edge Linux stable 才 143），声称 Edge 会引入
「声称了一个不存在的 Edge 版本」这种新的矛盾。Chrome 与 Chromium 同引擎、同版本号，
是代价最小的自洽选择。

**那容器里装真正的 Edge 会不会更好？** 实测数据：

| | Chromium (Debian) | Microsoft Edge (Linux stable) |
| :--- | :--- | :--- |
| 安装后占用 | ~267 MB | ~607 MB |
| 下载体积 | ~73 MB | ~172 MB |
| 依赖 | 43 个 | 37 个 + 需引入微软 apt 源与签名密钥 |

结论：装 Edge 只解决「品牌」这一项矛盾，**版本矛盾与系统矛盾依然存在，TLS 指纹也不会因此改变**，
却要多付约 340MB 镜像体积和一层外部依赖。所以默认不装；需要时可以通过环境变量
`CHROMIUM_PATH`（Dockerfile 里默认指向 `/usr/bin/chromium`）自行指向容器内的 Edge 可执行文件。

### 驱动层：patchright 与会话持久化（v1.6.2）

上面几条解决的是「字段自相矛盾」，但还有一个更硬的识别点：**自动化驱动本身**。
Playwright 启动 Chromium 时会启用 CDP 的 `Runtime.enable`，页面只要给 `console.debug`
挂一个 getter 就能探测到 CDP 的存在——这跟 UA 写得多像没关系。

v1.6.2 把驱动换成了 [patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright)
（Playwright 的补丁分支，API 完全一致），它从协议层修掉了 `Runtime.enable` /
`Console.enable` 泄漏，并去掉 `--enable-automation` 启动参数。

同时，每个账号的浏览器会话（Cookie + localStorage）会加密权限（0600）落盘到
`data/sessions/`，下次执行直接复用，浏览器看起来始终是同一台机器，而不是每次都是
「刚装好的浏览器 + 突然出现的登录态」。两条安全约束：

- 写回时**剔除 `.bing.com` 的 `_U` Cookie**：它是账号身份标识，上一轮残留的旧值一旦被
  带进下一轮就会串号或被重定向到登录页。配置里的 `_U` 每次启动都会重新注入，不影响计分。
- 会话**绑定账号凭据指纹**：Cookie/Token 换成别的账号后，旧会话直接作废，不会把 A 账号的
  浏览器状态带到 B 账号上。

### 仍然无法消除的差异（如实说明）

- **TLS / HTTP2 指纹**：纯 HTTP 通道走的是 Node 的 OpenSSL，与 Chromium 的 BoringSSL 不同。
  这不是改 UA 或请求头能解决的，只有真正用浏览器发请求才能一致。
- **渲染与硬件特征**：无 GPU 环境只能软件渲染，本项目把 WebGL 标识改成了常见核显，
  但更深层的渲染差异无法完全消除。
- **行为特征**：请求节奏、鼠标轨迹等属于另一层检测，本项目只做了基础的随机化与限速。

一句话：**这些手段能消除「自相矛盾」这种廉价识别点，但不能让自动化变成真实用户。**
真正决定账号安全的是地区、频率与行为是否克制。

## ❓ 常见问题 (FAQ)

### Q1：明明刚复制的 Cookie，为什么还是显示「已过期」？

**答**：绝大多数「刚复制就过期」并不是真的过期，而是复制下来的东西根本构不成登录态。现在代码会把原因分开说清楚，不再一律丢一句「Cookie 已过期」：

1. **只复制了某一个值**：比如只贴了 `_U` 后面那段 GUID，或某个 200 字符的 token，没有 `名=值` 结构。这种输入永远不可能登录成功——现在会直接提示「这只是一个值，需要完整的 Cookie 串」，并给出用 `document.cookie` 复制的具体步骤。唯一的例外是只贴了 `_U` 的 GUID 值本身：那会自动补成 `_U=...` 并合并进账号已有的 Cookie，不会把其它项冲掉。
2. **缺少 `_U` / `MUID`**：`_U` 是必应身份标识，缺了它页面能打开、积分能读，但**搜索一定不计分**；`MUID` / `RPSSecAuth` / `WLS` 缺失说明登录态不完整，rewards 页面可能直接跳登录。现在会明确列出**缺了哪几项**，并且能从 `SRCHUID` / `_EDGE_S` / `SRCHHPGUSR` 里交叉校验出同一个 `GUID=` 时自动补齐 `_U`（几处不一致就拒绝猜，提示重新复制）。
3. **复制到了别的域名下的 Cookie**：`login.live.com`、`account.microsoft.com` 等站点各自有自己的一套 Cookie，混进 `rewards.bing.com` 需要的串里只会带上无关项。登录窗口只采集微软域名下的 Cookie，所以它拿到的才是干净的整套——这也是它比手工复制可靠的原因。
4. **会话是真的过期了**：当官网把请求重定向到登录页（`login.live.com/oauth...` / `account.microsoft.com/auth|login`）、或页面被判定为游客态时，代码会如实报告「登录态已失效」而不是含糊的过期；这种只能重新登录，首选「🌐 打开登录窗口自动获取 Cookie」。

### Q2：为什么提示“非中国大陆 IP，已自动停止”？
**答**：微软 Rewards 会严格检测用户 IP 地区。如果是中国区账号但在境外 IP 上打卡，极易被微软风控（封号、无法兑换礼品卡、任务跳区）。为保护您的账号安全，程序默认启用了国区安全锁。境外 VPS 用户请在配置中心开启代理并走国内节点。

### Q3：网页端 Cookie 会过期吗？需要经常更新吗？
**答**：微软网页 Cookie 通常有效期长达数周至数月。移动端的 OAuth Token 则由程序通过 Refresh Token 自动在后台刷新续期，无需手动干预。若 Cookie 真的失效，控制台及推送通知会主动提示你重新获取——优先用「🌐 打开登录窗口自动获取 Cookie」，比手工复制可靠得多。

### Q4：如何备份我的配置数据？
**答**：所有配置文件、任务进度、统计历史与浏览器会话均保存在映射的 `./data` 目录中（包括 `config.json`、`stats.json`、`sessions/` 与登录窗口使用的 `login-profile/`）。更换设备时只需打包转移 `data` 目录即可实现无缝迁移。若想强制所有账号「重新登录一次」，删掉 `data/sessions/` 与 `data/login-profile/` 即可，不会影响任务进度与积分历史。
